So an originated option strategy can become a CANDIDATE and backtest correctly, but **cannot be promoted-to-live-and-traded** — there is no broker options lane.

## 6. SP-4 lessons learned (apply in SP-5, esp. for any real-run proof)

- **Proof harness env bug:** prod `.env` sets `OPENCLAW_DIR=/root/openclaw`. Loading `.env` into a proof's env makes the orchestrator + subagent CLI read prompts/skills from **main, not your worktree** — silently testing the wrong code. **Force `OPENCLAW_DIR` to the worktree** in any proof.
- **Skill schemas are authoritative for subagent output.** PaperHunter/StrategyCoder anchor on the `fundjohn:paper-to-strategy` / `fundjohn:strategy-coder` SKILL.md JSON schemas (`src/plugins/fundjohn/skills/*/SKILL.md`). A new output field added only to the `.md` prompt was **dropped by Sonnet** until it was added to the SKILL schema too. If SP-5 adds any new emitted field, put it in the SKILL schema.
- **Subagent uid vs worktree ownership:** `run-subagent-cli.js` spawns `claude-bin` as `claudebot` (uid 1001). A root-owned worktree blocks the subagent's file writes. For a proof that needs the subagent to write the worktree, `chown -R claudebot:claudebot` the relevant dirs (prod `/root/openclaw` is already claudebot-writable). Do NOT escalate the subagent to root (the auto-mode classifier blocks `CLAUDE_UID=0`).
- **Gate-OFF byte-identity discipline:** every new code branch should key on its gate or default to the legacy value, so merging is inert until the operator flips the gate. SP-4 merged inert, then activated as a separate deliberate step. Prod DB DELETEs require explicit operator consent (the classifier enforces this).
