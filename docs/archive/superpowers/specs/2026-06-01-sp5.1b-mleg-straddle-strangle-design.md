# SP-5.1b — Multi-leg Long Straddle/Strangle Execution Lane + Delta-Hedge (Design)

- **Date:** 2026-06-01
- **Parent project:** SP-5 *close-the-loop* (options execution). Follows SP-5.1a (single-leg, merged to `main` `39c303e`).
- **Status:** design approved; awaiting spec review → writing-plans.

## 1. Goal & scope

Add a **live execution lane for long straddles and long strangles**, with **delta-hedging**, reusing the SP-5.1a single-leg primitives. `OptionSpec` already supports `structure ∈ {single, straddle, strangle}` and `hedge ∈ {none, delta}`; the backtest (`options_backtest.py`) already prices these structures. SP-5.1b adds the live exec path so an originated straddle/strangle candidate can trade.

**In scope:** long straddle + long strangle, `hedge='none'` and `hedge='delta'`.

**Out of scope (future):** short premium of any kind (naked barred at L3 — see SP-5.0); defined-risk credit spreads / verticals / iron condors (SP-5.2 — needs `OptionSpec` structure-enum extension + the mleg credit `limit_price` sign question); single-name / OTM-wing underlyings beyond the index/ETF ATM envelope SP-4 supports.

**Activation model:** ship inert (gate-OFF/byte-identical), like every SP-3/4/5 increment; flip only when a Saturday-originated straddle/strangle candidate clears the `option` promotion gate (Sharpe 0.80 / MaxDD 0.30).

## 2. Locked decisions (brainstorm 2026-06-01)

1. **Envelope:** straddle + strangle + delta-hedge (full).
2. **Greeks source:** **live Alpaca chain greeks** (`data option chain` per-contract `delta`) for both the strangle `target_delta` strike selection and the hedge ratio. Diverges from the backtest's BS greeks — documented as a parity note, not a defect. Also upgrades 5.1a's crude `target_delta` offset heuristic to real delta-matching.
3. **Rehedge cadence/placement:** initial hedge at entry + daily rehedge, **produced at the 4 PM EOD compute and filled T+1** via the SP-6 EOD pipeline (see §3) — not a legacy 10 AM cycle step.
4. **Hedge attribution:** a **dedicated hedge ledger** (new table) keyed by option `strategy_id`. The ledger is the sole source of truth for the hedge position; hedging never reads the total broker book, so equity strategies on the same underlying are structurally invisible.

## 3. Framework fit — delta-hedge as an EOD *target producer*

The live daily cycle is migrating (SP-6 Phase A) from same-day-close execution to **compute-at-`close[T]` / act-`T+1`**:

| When | SP-6 step | Lifecycle |
|---|---|---|
| T, 4:00 PM | EOD compute — `daily-cycle.js` `[collect, sentiment, signals]`, reason `eod-signal-register`; writes T+1 targets to `execution_signals` `lifecycle_state='COMPUTED'` | → COMPUTED |
| T+1, ~9:15 | Carry-forward gate (panic/sentiment) | COMPUTED → APPROVED/REJECTED |
| T+1, 9:30 | Reconcile — diff APPROVED vs book (drops→OPG close; new/resize→algo) | APPROVED → EXECUTING |
| T+1, fill | Phase A: naive fill into `close[T+1]`. **Phase B = the "optimal order submission process"** (alpha-conditioned scheduler) — not yet built | EXECUTING → FILLED |
| T+1, 4:00 PM | EOD compute again + finalize `close[T+1]` parity mark | — |

**The delta-hedge is a target producer, not a submitter.** It emits hedge positions into the *same* `execution_signals` COMPUTED→…→FILLED pipeline the production sizer uses, so the SP-6 reconcile/fill machinery executes the hedge with **zero hedge-specific submission logic**:

- At **4 PM[T] EOD compute**, a new `compute_option_hedge_targets` pass runs after `signals`: for each live delta-hedged structure, pull day-T close greeks (live chain `delta` per leg), compute net structure delta, and write the **target hedge share position** (`= −Σδ × 100 × contracts` on the underlying) as a COMPUTED `execution_signals` row — attributed to the option `strategy_id`, tagged `is_hedge`.
- A **new** structure registered that same EOD emits its **initial** hedge target alongside it (strikes already resolved from the day-T chain), so structure + hedge both fill T+1 — matching the backtest, which enters the structure and hedges at the *same* `close[t+1]` bar.
- **9:30[T+1] reconcile** diffs the hedge target against `ledger.current_hedge_qty` (not the raw book) → only the *delta-to-target* shares route → EXECUTING → fill.
- The decide(T)→fill(T+1) lag is inherent and **parity-consistent**: the backtest rehedges daily at close and now fills t+1, so live "decide at `close[T]`, fill T+1" mirrors it.

**Why this seam:** the hedge never needs to know *how* orders are submitted. It produces targets; the SP-6 pipeline consumes them — Phase A's naive into-close fill today, Phase B's optimal scheduler unchanged when it lands.

## 4. Components & data flow

New surface in **bold**. Split by the exec-then-hedge sequencing (§7).

### 4.1 — 5.1b-i: mleg straddle/strangle execution (builds on `main`)

Extends the single composition point `src/execution/alpaca_executor.py:_route_option_order`; reuses every 5.1a primitive.

- **`_route_option_order` (extend):** remove the `structure != 'single'` skip for `straddle`/`strangle` (single-leg path unchanged; verticals/condors still skip — SP-5.2). Resolve one expiry (`_resolve_expiry`), then resolve legs per `structure`:
  - **straddle** → `[(call, K_atm), (put, K_atm)]` — one ATM strike via `_resolve_strike` atm path.
  - **strangle** → call leg at the listed strike whose live `delta ≈ +target_delta`; put leg at `delta ≈ −target_delta`.
- **`_option_chain_greeks(underlying, expiry, right, spot)` (new):** strike-band chain fetch (`data option chain --underlying-symbol U --expiration-date E --type {call|put} --strike-price-gte/lte` over a band around spot, default ±15%; paginate via `--page-token` if the band exceeds the 100-row page) returning `(strike, delta, occ)` per contract. The strangle picks `min |delta − target|`. This is also the real-greeks upgrade of 5.1a's documented `target_delta` heuristic in `_resolve_strike`.
- **Quote + limit:** per-leg `_option_quote` (the SP-5.1a `latest-quotes` helper) → net debit = Σ(ask); marketable `--limit-price` = net + slip; `limit_price_override` (the SP-5.1a sentinel hook) still forces a non-marketable rest for probes.
- **Sizing:** `contracts = floor(notional_usd / (net_premium × 100))`; both legs `ratio_qty = "<contracts>"` (1:1); the 5.1a sub-contract guard (`_resolve_option_qty`) is reused on the net premium. Long debit ⇒ **no** cash-collateral guard (that path is short-put-only).
- **Position-intent:** per-leg `_options_current_qty` → `_options_position_intent` (each leg `buy`/`buy_to_open` for a fresh long; the SP-5.0 test-5 422 fix).
- **Submit:** `order submit --order-class mleg --legs '[{symbol,side:"buy",ratio_qty:"<n>",position_intent:"buy_to_open"} × 2]' --type limit --limit-price <net> --time-in-force day --client-order-id <coid>`. (`ratio_qty` MUST be a string — SP-5.0 grounding.)
- **Close:** preferred = single mleg **sell-to-close** package (both legs, marketable net-credit limit) to avoid legging risk — but this hits the same unresolved mleg credit `limit_price` sign as a credit spread, so it is **gated on the Task-0 credit-sign result (§8.1)**. **Fallback if the credit sign is unconfirmed:** close each leg via per-leg `position close` (the proven SP-5.1a path) — accepts brief legging risk on a 2-leg liquid-index close, which is acceptable for the inert MVP. Either way: per-leg `_options_current_qty` flat-verify after (never trust the ack).
- **`record_submission`:** mleg rows carry `instrument_class='option'` (migration 122, already live) + the leg set; structure recorded for the hedge subsystem to reference.

### 4.2 — 5.1b-ii: delta-hedge subsystem (stacks on/after SP-6 Phase A)

- **Migration 126 (new — verify next-free at build; 127 is reserved by the unmerged Phase-B0 branch): `option_hedge_ledger`.** Columns: `id`, `option_strategy_id`, `underlying`, `structure_legs` (JSON: the hedged OCC legs + contracts), `current_hedge_qty NUMERIC` (signed shares, filled), `target_hedge_qty NUMERIC` (signed, last EOD), `last_rehedge_date`, `status` (`active`|`closed`), `created_at`, `updated_at`. **Operational mutable state — NOT a master/canonical append-only table** (`current_hedge_qty` is updated in place on each fill); keyed by option `strategy_id`. **The ledger is the sole source of truth for the hedge position; hedging never reads the total broker book** — equity strategies on the same ticker are structurally invisible (the crypto "equity-untouched" guardrail, inverted). Not master data; row updates allowed.
- **`src/execution/option_hedge.py` (new):**
  - `compute_structure_delta(legs, contracts) -> float` — Σ (live chain `delta` per leg) × 100 × contracts.
  - `compute_option_hedge_targets(as_of)` — for each `active` ledger row + each new delta-hedged structure registered this EOD: compute `target = −structure_delta`, write a COMPUTED `execution_signals` row on the underlying tagged `is_hedge` + `hedge_strategy_id`, and upsert `ledger.target_hedge_qty`.
- **EOD wiring:** `compute_option_hedge_targets` runs inside the 4 PM[T] `eod-signal-register` step, **after `signals`** (the equity targets), so hedge targets join the same carried set.
- **Reconcile/fill hook:** hedge-tagged targets net against `ledger.current_hedge_qty` (not the book); the *delta-to-target* routes through the normal 9:30 reconcile → EXECUTING → fill; on fill, `current_hedge_qty` is updated from the **real fill** (rides SP-6 Phase B0 fill-persistence). Phase A fills into `close[T+1]`; Phase B's optimal scheduler inherits it unchanged.
- **Close/unwind:** closing the structure flips the ledger row to `status='closed'` and emits a hedge target of **0** (flatten the hedge) through the same EOD→T+1 path.

## 5. Safety, parity, error handling

- **mleg atomicity** — rely on Alpaca's all-or-nothing `mleg` fill (no partial-leg legging); **verified in the Task-0 spike (§8)**, not assumed.
- **Position-intent 422** — per-leg `_options_current_qty` → `*_to_open`/`*_to_close` (SP-5.0 test-5 fix, reused).
- **RTH-only** — options orders RTH-only (`_options_session_gate`). The 4 PM EOD compute is post-close; it reads the **close** greeks snapshot (or the ~3:55 pre-close snapshot if post-close greeks are stale — resolved in §8). The hedge *equity* order is RTH-fillable T+1.
- **Flatten-health guard** — hedge targets honor SP-6's `eod_compute_health` GREEN gate; a RED/empty EOD compute never emits or zeroes a hedge (the 2026-05-22 empty-signals blowout class).
- **Ledger ↔ broker reconciliation** — `current_hedge_qty` is updated only from **real fills** (Phase B0); ledger-vs-broker disagreement beyond tolerance → alert + preserve, never blind-trade.
- **Equity-untouched invariant** — the load-bearing test: a mixed equity-SPY + hedge-SPY book → hedging touches only the ledger's portion.
- **Fail-closed everywhere** — every resolve/greek/quote step fail-closes (5.1a pattern); a missing leg quote, an unresolved delta-match, or an empty chain band → skip the whole structure, no partial submit.
- **Parity** — straddle=ATM, strangle=`target_delta` legs reproduce the backtest's `options_backtest._legs_for`; the live-chain-greeks vs BS-greeks divergence is documented (decision §2.2); the option structure rides SP-6's COMPUTED→FILLED lifecycle + `close[T+1]` parity mark like any other signal (option "close[T+1]" mark = the structure's net close price; brackets are pct-of-premium).

## 6. Gating (default-OFF; inert until a candidate promotes)

- mleg exec rides the existing `OPENCLAW_OPTION_EXEC` (already live, default-OFF). With it off, `_route_option_order` returns `None` for all structures (byte-identical equity path).
- The delta-hedge subsystem gets its own `OPENCLAW_OPTION_DELTA_HEDGE` (default-OFF), so it can be flipped independently and stays off until SP-6's EOD gates are live. **Doctor asserts the dependency** (`OPENCLAW_OPTION_DELTA_HEDGE=1` requires `OPENCLAW_EOD_SIGNAL_REGISTER=1` + `OPENCLAW_EOD_RECONCILE=1`).

## §6. DESIGN CORRECTION — delta-hedge integration (2026-06-01, operator-approved)

Implementing 5.1b-ii against the real SP-6 seams (and an advisor review) showed §4.2's **exclusion** model is wrong. This section SUPERSEDES §4.2's hedge-integration mechanics. (§4.1 mleg exec — SP-5.1b-i, merged — is unchanged.)

**Why exclusion was wrong:** SP-6 nets *per-ticker* (`target_usd[t] − broker[t]`), and the 9:30 `run_reconcile` orphan-closes any broker ticker NOT in the APPROVED set. Subtracting the hedge from the broker book either (a) freezes the hedge (it's never rehedged) or (b) double-counts when combined with a hedge target row. And an untracked hedge position would be orphan-closed at the open.

**Corrected model — hedge as an INJECTED, net-aggregated APPROVED row:**
1. **Injection, not exclusion.** The EOD step writes the hedge as a real `execution_signals` row on the underlying carrying a FIXED share target (`hedge_shares` in `signal_params`; direction = sign of `−net_structure_delta`). The sizer adds `hedge_shares × price` to `target_usd[underlying]` (the sizer already aggregates multiple strategies' contributions per ticker — the hedge is one more contribution). The broker stays total; per-ticker netting (`target − broker`) auto-computes the rehedge delta. NO broker exclusion.
2. **Net-aggregate on shared tickers (operator decision A).** Hedge + equity on the same ticker (e.g. hedge short SPY + an equity strategy long SPY) net into ONE signed per-ticker target. The sizer's `target_usd` sum already does this. The **9:30 reconcile must be taught to net signed QTY per ticker** — `_load_approved_set` currently collapses to a single ±1 sign per ticker; it must instead sum the signed share targets of all APPROVED rows for a ticker (incl. the hedge row) and use the NET sign for orphan/flip classification. **This is a real change to live SP-6 reconcile behavior — the load-bearing, highest-stakes task; design + review carefully.**
3. **Hedge rows BYPASS the premarket panic/sentiment gate (operator decision B).** A risk hedge must not be sentiment-vetoed into REJECTED (→ orphan-closed → unhedged structure). Hedge rows are written directly `APPROVED` (or the gate auto-approves `is_hedge` rows), following the structure's lifecycle, not a fresh alpha veto.
4. **No `current_hedge_qty`, no fill-tracking (drops plan T7).** SP-6 Phase A marks to `close[T+1]` with a zero-width execution ledger, so the hedge is **mark-to-target**: re-derive the hedge TARGET each EOD from live greeks; the broker total + per-ticker netting reconciles it implicitly (day T+1: target 25, broker 30 → sell 5). The ledger row holds only the structure legs + the latest target (for the EOD recompute + close-detection). T8's check becomes **stale-target** (a structure whose hedge target wasn't recomputed recently), not ledger-vs-broker reconciliation.

**Net effect on the plan:** T1–T3 (migration + CRUD + `compute_structure_delta`) stand (the migration's `current_hedge_qty` column becomes vestigial/unused — harmless, leave it). T4 carries `hedge_shares` + writes APPROVED (gate-bypass). T6 = sizer target-injection + **reconcile net-signed-qty aggregation** (the live change). **T7 is dropped.** T8 = stale-target check.
