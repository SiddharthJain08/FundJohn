## Problem

Two gaps, one seam:

1. **Expiry is unmanaged.** Held option legs ride to expiry with zero handling. An ITM leg
   expiring means exercise/assignment → a surprise equity position + cash impact the system
   never modeled. Final-week gamma/pin risk is where unmanaged positions get dangerous.
   Hard prerequisite before any organic candidate holds multi-day option positions.

2. **Option opens are held-position-blind — daily stacking (activation-safety gap).**
   Confirmed by direct read 2026-06-04, nothing dedups:
   - the EOD carried set re-loads a persistent signal daily
     (`_load_approved_carried_signals`) — it is the *signal persistence* mechanism, not a
     dedup;
   - `_consolidate_option_orders` emits plain opens (`current_usd=0.0`, "options never net
     the equity broker map" — by design);
   - `regime_blended_sizer_live` routes without held-awareness;
   - `alpaca_executor._route_option_order`'s OPEN path classifies → gates → validates →
     resolves expiry → **submits**. No held check anywhere.

   So any candidate that signals persistently within its cadence window stacks a fresh
   mleg structure **every trading day** once `OPENCLAW_OPTION_EXEC=1`. The 5.1c reference
   candidate dodged this only by strategy-level discipline ("re-open monthly") — fragile.
   **The 5.1c runbook's "armed — one-step activation" exit state is therefore incomplete:
   5.3 prong 1 is an activation prerequisite.** (T9 is immune — same-session open+close.)

## Operator-locked decisions

- **SP-5.3 scope = expiry/roll management** (chosen over intraday rehedge [B1-gated],
  organic-candidate readiness, new structures).
- **Roll policy = force-close at T−N, organic reopen.** No explicit roll primitive: the
  strategy's own next signal reopens at fresh `dte_target≈22` through the normal
  consolidation path once the book is flat. Exposure gap = **up to one full trading
  session** (close at 3:55 ET day T, reopen earliest 3:55 ET day T+1) — accepted.
- **DTE floor = 7 calendar days, single rule** for all structures (chosen over
  split short-premium/long thresholds and over 5 days).

## Design — two prongs, one seam

Both prongs live inside the existing `OPENCLAW_OPTION_EXEC == '1'` block in
`_sharpe_cadence_path` (`src/execution/regime_blended_sizer.py`), beside the G4b
orphan-close. **Gate-off remains byte-identical** (everything new is inside the gate;
the unconditional `orders.extend(_opt_orders)` moves below the gate block but executes
an unmodified list when the gate is off). **Gate-ON behavior changes — that is the
point.** The advisor-reviewed truth table:

| held? | in targets? | min DTE ≤ 7? | emission |
|-------|-------------|--------------|----------|
| yes | no  | any | orphan close *(existing G4b, unchanged)* |
| yes | yes | no  | **suppress open** (new) — hold the position, log |
| yes | yes | yes | **expiry close** (new, `__close_option_expiry__`) + suppress open |
| no  | yes | —   | open *(existing, unchanged)* |

### C1 — OCC DTE parser

`_occ_dte(occ, today) -> int`: calendar days to expiry from the OCC tail
(`occ[-15:-9]` = yymmdd; the `_OCC_RE` filter in `_held_option_underlyings` already
guarantees 6 digits there). Min across held legs per underlying. **Parse failure
(invalid date like 999999) → warn loudly + treat as DTE 0** — an unreadable expiry is
an unmanageable position; close it. Boundary: `dte <= 7` closes (fires on T−7).
Threshold = module constant `OPTION_EXPIRY_CLOSE_DTE = 7`, env-overridable via
`OPENCLAW_OPTION_EXPIRY_CLOSE_DTE` (parse-guarded, falls back to 7).

### C2 — held-open suppression (prong 1, the activation-safety fix)

Inside the gate block, after computing the held map: drop every open in `_opt_orders`
whose underlying has held legs, with a loud per-underlying log
(`option open SUPPRESSED for %s — structure already held (%d legs)`). Consequences,
intentional: option targets are never delta-rebalanced while held (lifecycle stays
"owned by the executor"; greeks-aware sizing remains deferred per 5.1c); the hedge
ledger row stays active while held so EOD hedge targets keep flowing — correct.

### C3 — expiry close (prong 2)

For a held underlying that IS in today's targets with min-DTE ≤ 7: append a forced
close using the **exact orphan-close emission shape** with
`strategy_id='__close_option_expiry__'` and
`option_spec={'underlying': U, 'structure': 'held_legs'}`. It rides the proven chain:
executor close dispatch (keys on `close_only` + structure ≠ 'single', NOT on
strategy_id — TDD asserts this rather than assumes) → `_route_mleg_close` (per-leg
`position close` + one re-flatten retry; the long-leg residual pattern from 5.2/5.2b) →
G4c `deactivate_hedge_ledger_for_underlying` (hedge cleared next EOD compute; on the
organic reopen's fill, `upsert_hedge_ledger_on_fill` re-creates it). The
held-but-NOT-in-targets case stays the orphan close's job regardless of DTE (no double
close; truth table rows are disjoint).

Retry-by-construction: if the close fails or partially fills, the legs are still held
next cycle and the signal is still in targets with DTE ≤ 7 → the expiry close re-emits
daily until flat. Escalation backstop is C5.

### C4 — held-fetch error-vs-empty hardening (closes the 5.1b-i known follow-up)

`_held_option_underlyings()` currently returns `{}` on ANY error — indistinguishable
from a legitimately flat book ([[feedback_silent_failure_pattern]]). With suppression
in play that's no longer benign: a broker CLI hiccup at 3:55 would skip suppression
and stack an open on a held underlying. Contract change: **return `None` on fetch
error, `{}` on genuinely-empty.** On `None`, the gate block fail-closes for OPENS —
suppress ALL option opens this cycle + log error (can't prove flat → don't open);
orphan/expiry closes are also skipped that cycle (can't enumerate held legs), which is
safe because the close re-emits daily and C5 backstops. Sole production caller is the
G4b block (verified); tests updated for the new contract.

### C5 — doctor check `option_expiry_floor` (belt-and-suspenders)

New read-only, **unconditional** (gate-independent) check in `src/maintenance/doctor.py`
(registered via the existing `@_check` decorator, WARN/FAIL severity convention
verified): scan the broker book
for held OCC legs; any leg with DTE ≤ 3 → **FAIL** (loud, names the legs); otherwise
PASS reporting min DTE across held legs (or "no option legs held"). Catches the
EOD-cycle-died-during-expiry-week case (4 daily retries between T−7 and T−3 must all
have failed before this fires). Gate-off it doubles as a stray-option-position
detector. Broker fetch failure → WARN (not FAIL) — consistent with doctor's existing
degraded-data convention.

### C6 — runbook + memory exit-state amendment

Amend `docs/superpowers/runbooks/2026-06-03-sp5-options-activation-runbook.md` (the
armed-state activation procedure) + memory: **one-step activation
(promote→smoke→flip) additionally requires SP-5.3 deployed** — without prong 1, any
persistently-signalling candidate stacks daily. Also note the reference candidate
simplifies: with 5.3 live it may signal continuously; infra owns the lifecycle (no
strategy-level state tracking, no self-managed roll).

## Non-goals (deferred)

- Explicit/atomic roll primitive (close+reopen same cycle or mleg roll order) — rejected:
  largest new surface, duplicates what the sizer already does on open.
- Standalone expiry timer — rejected: duplicates gating/reporting/execution wiring and
  doesn't fix stacking. Executor-side dedup — rejected: wrong layer (executor executes;
  the sizer owns portfolio decisions).
- Assignment-aftermath cleanup. Prevention (T−7 + retries + doctor floor) makes it rare;
  if it ever happens, the assigned position appears as plain equity in the broker book,
  is absent from targets, and the existing reconcile/sizer orphan-close machinery closes
  it — crude but safe. Revisit only if observed.
- Greeks-aware delta-dollar option sizing (still deferred to real candidate promotion,
  per 5.1c).
- Intraday rehedge (B1-substrate-gated, per the activation runbook).
- Delta-rebalancing of held option structures (suppression means hold-as-is until close).
- Multi-expiry stacks per underlying: min-DTE governs the whole underlying;
  `_route_mleg_close` closes ALL held legs for the underlying (consistent with
  first-spec-wins / one-structure-per-underlying consolidation).

## Testing (TDD, stacking-bug-first)

1. **RED first:** a two-cycle test with a persistent option signal + a held-legs stub
   proving TWO opens are emitted today (documents the live bug) → C2 makes the second
   cycle a no-op → GREEN. This test is the permanent stacking guard.
2. Expiry close: held+in-targets leg at DTE=7 → `__close_option_expiry__` emission with
   held_legs spec; DTE=8 → no close, open suppressed; held+NOT-in-targets at DTE≤7 →
   orphan close only (exactly one close).
3. Dispatch assertion: the `__close_option_expiry__` order routes through
   `_route_mleg_close` (not strategy_id-dependent).
4. C1 unit tests: boundary 7/8, parse-failure → 0 + warn.
5. C4: fetch-error (None) → ALL opens suppressed + error log; empty ({}) → opens flow.
6. Gate-off parity: gate unset → emissions byte-identical to pre-5.3 (no suppression,
   no expiry close, no extra CLI calls).
7. Orphan-close regression: orphan-close BEHAVIOR unchanged; G4b tests stay green —
   except `test_g4b_no_close_when_live_option_target`, whose open-side assertion
   necessarily flips for C2 (held+targeted open now suppressed), and the failsafe
   test, which adopts the C4 None contract. (Wording corrected post-build per the
   final whole-branch review.)
8. C5 doctor tests: FAIL at DTE≤3, PASS otherwise, WARN on fetch failure.
9. SP-6 cap adjacency: per-ticker-cap tests (`test_sizer_per_ticker_cap.py`) stay green
   — 5.3 edits the same function.

## Risks

- **Close keeps failing through expiry week:** daily re-emission (retry-by-construction)
  + doctor FAIL at DTE≤3 + the existing Discord executor summary surface it. Worst case
  is the pre-5.3 status quo (ride to expiry) — 5.3 strictly improves.
- **Suppression hides a sizing drift:** intentional and documented (C2); revisit with
  greeks-aware sizing.
- **Same-cycle close+open hazard** (close would flatten the NEW legs since
  `_route_mleg_close` closes all legs per underlying): structurally impossible —
  suppression covers every held underlying, so an open never co-emits with a close.
- **Holiday/weekend compression:** 7 calendar days ≈ 4-5 RTH sessions of retry buffer;
  accepted with the T−7 choice.
