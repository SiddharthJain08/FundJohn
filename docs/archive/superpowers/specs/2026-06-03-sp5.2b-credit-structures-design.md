## The unblocking fact (docs grounding DONE 2026-06-03)

Alpaca's API reference (`POST /v2/orders`, `limit_price` field) documents the mleg convention explicitly:

> "In case of `mleg`, the limit_price parameter is expressed with the following notation: A positive value indicates a debit, representing a cost or payment to be made. A negative value signifies a credit, reflecting an amount to be received."

**The convention is SIGNED: negative limit = net credit (receive ≥ |X|).** This resolves SP-5.0 §4a's anomaly: the "+$50 credit" limit on the test-4 short call vertical actually meant "willing to PAY up to $50" — trivially marketable for any credit fill, hence the instant fair-value fill. The correct credit-spread limit is negative.

Two conveniences fall out:
1. `_structure_net_quote` (SP-5.2) already returns the **signed** net (Σ buy ask − Σ sell bid), which is naturally **negative for a credit structure** — identical sign convention to the API.
2. The marketable pad is **uniform**: `net + 0.02` means "pay up to 2¢ more" for debits and "accept 2¢ less credit" for credits. One formula, both sides.

**Remaining live-probe items (Task 0):** (a) the Go CLI's `--limit-price` flag with a negative value (likely needs `--limit-price=-4.48` to avoid negative-arg parsing); (b) a non-marketable credit limit must REST, not fill (the inverse of the SP-5.0 mistake); (c) the live iron-condor submit (4-leg construction already broker-validated in the SP-5.0 cleanup dry-run; live submit pending).

## The structures

- **`credit_vertical`** (2 legs, same right, net credit): SELL near (short leg, closer to ATM) + BUY far (wing, further OTM). `right='call'` → bear call spread (far ABOVE near); `right='put'` → bull put spread (far BELOW near). Max loss = (width − credit)×100. Sold (short the package).
- **`iron_condor`** (4 legs, all ratio 1 — satisfies the documented GCD-1 rule): short call spread above spot + short put spread below spot: `[SELL call nearC, BUY call farC, SELL put nearP, BUY put farP]`. Max loss = (max wing width − credit)×100. Sold.

## Components

### C1 — `OptionSpec`: two new structure values (no new fields)
- `structure` domain += `'credit_vertical' | 'iron_condor'`.
- Strike resolution REUSES existing fields: the short (near) legs via `strike_rule`/`target_delta` (condor: the same `target_delta` applied per side — call side above spot, put side below); wings via `spread_width_pct` (far = near ± pct×spot, AWAY from spot, snapped to a listed strike).

### C2 — Leg resolution (`_resolve_structure_legs`)
- `credit_vertical`: near = `_resolve_strike(spec)` for `spec.right`; far = near ± `spread_width_pct×spot` away from spot (call: higher; put: lower), snapped to the nearest listed strike from `_option_chain_greeks`. Legs: `[(right, near, 'sell'), (right, far, 'buy')]`. Fail-closed: any unresolved, `far == near`, or `spread_width_pct ≤ 0` → None.
- `iron_condor` (`spec.right` is IGNORED — the structure spans both rights): for each side: nearC = strike nearest `+target_delta` on calls; nearP = nearest `−target_delta` on puts (the strangle-style delta-match, reused); farC = nearC + width×spot (snapped); farP = nearP − width×spot (snapped). Legs: `[('call', nearC, 'sell'), ('call', farC, 'buy'), ('put', nearP, 'sell'), ('put', farP, 'buy')]`. **Strike-ordering sanity guard (fail-closed): `farP < nearP < spot < nearC < farC`** — protects against degenerate chains/deltas producing crossed or inverted strikes.

### C3 — Intent-aware envelope + net guard (`_route_option_order`)
- Structure admission: add both to the allowed set + the mleg branch + the close dispatch.
- **Direction guard becomes structure-aware:** `single|straddle|strangle|vertical` → require `'long'` (UNCHANGED — naked short premium still refused); `credit_vertical|iron_condor` → require `'short'` (the package is sold; SELL_VOL normalizes to 'short'). A `'long'` credit structure is refused (use `vertical` for debit exposure).
- **Net guard becomes intent-aware:** debit structures require `net > 0` (unchanged, 5.2's guard); credit structures require `net < 0` (must genuinely collect premium; `net ≥ 0` = crossed/degenerate quotes → skip).
- **Limit:** uniform `net_limit = round(net + 0.02, 2)` (negative for credits). Submit passes the negative limit using the Task-0-probed CLI syntax (expected: `--limit-price=-4.48` single-token form).
- Hedge guard: credit structures require `hedge='none'` (delta-hedging short premium is out of scope).

### C4 — Close
- Per-leg `position close` via the existing structure-agnostic `_route_mleg_close`/`_held_option_legs` (reads held legs by underlying; buy-to-close shorts proven live in 5.2). Only change: close-dispatch admission for the new structures (C3).

Findings → `2026-06-03-sp5.2b-grounding-snapshot.md`; the submit code locks to them.

- **Supervised smokes (operator-OK at fire time, RTH):** small marketable credit-vertical fill → per-leg close → flat-verify; iron-condor fill → per-leg close (4 legs) → flat-verify. Proves margin/collateral acceptance + the negative-limit fill semantics end-to-end.

## Data flow (gates-on, credit vertical)

```
order {direction:'short', option_spec: structure=credit_vertical, right=call, target_delta=0.25, spread_width_pct=0.03}
  → _route_option_order (OPENCLAW_OPTION_EXEC=1; structure-aware guard: credit → require short ✓)
  → _resolve_structure_legs → [(call, nearC, sell), (call, farC, buy)]
  → _structure_net_quote → net = farC_ask − nearC_bid  (negative = credit)
  → intent guard: net < 0 ✓ → net_limit = net + 0.02   (e.g. −4.48)
  → _build_mleg_legs_json (sell_to_open near, buy_to_open far — per-leg sides, 5.2 machinery)
  → alpaca order submit --order-class mleg --qty N --legs ... --limit-price=-4.48 --tif day
  → close: per-leg position close → flat-verify
```

## Risks & mitigations

- **Accidental marketable credit submit (the SP-5.0 failure mode):** prevented three ways — signed semantics from official docs; the intent-aware net guard (credit requires net<0, limit derived from the quoted net, never hand-set positive); Task-0 proves a non-marketable credit RESTS before any fill smoke.
- **CLI negative-arg parsing:** probed before the submit code is written; expected fix is the `=` single-token form.
- **Margin/collateral rejection on fill:** defined-risk at L3 (SP-5.0 test-4 credit spread FILLED live); the smoke re-proves under current account state. If the condor is margin-refused, the vertical smoke still completes the phase partially — surfaced to operator.
- **Byte-identical regression:** all changes are additive branches keyed on the two new structure values; the four existing structures' tests are the gate.
