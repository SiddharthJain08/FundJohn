# SP-5.1a — Single-leg Options Execution Lane (Design)

**Date:** 2026-05-29
**Status:** Design — drafted; pending operator review
**Program:** SP-5 (Close-the-loop options/futures exec), Phase 5.1a of {5.0 grounding ✓, 5.1a single-leg, 5.1b mleg, 5.2 vertical/condor (deferred)}
**Predecessors:**
- SP-3 instrument-class enum (option/etp/crypto/futures routed/reserved)
- SP-4 Phase 0 greeks-engine + `OptionSpec` dataclass (`src/strategies/base.py:21-37`)
- SP-5.0 grounding (`docs/superpowers/specs/2026-05-27-sp5-alpaca-options-snapshot.md`) — Alpaca L3 envelope confirmed: long premium ✓, defined-risk spreads ✓, **L1 cash-secured short put ✓** (verified 2026-05-28 13:35 UTC), naked short premium ❌

## 1. Goal

A **single-leg** option order originated by an SP-4-promoted strategy can route to the Alpaca broker and fill on the existing daily cycle, without disturbing the equity, ETP, or crypto execution paths.

**Concretely** — an `OptionSpec(structure='single', right='call'|'put', …)` with `Signal.direction in {'long','short'}` becomes:
- A submit-time OCC symbol (`<root><YYMMDD><C|P><strike×1000>`)
- A live-resolved strike from the target-delta/atm/fixed-moneyness rule
- An `alpaca order submit --symbol <OCC> --qty N --side buy|sell --type limit --limit-price L --time-in-force day --position-intent <…_to_open|…_to_close>`
- A correctly-shaped `alpaca_submissions` audit row (instrument_class='option', symbol=OCC, qty=contracts)

**Explicitly NOT in SP-5.1a** (each → its own follow-up):
- Multi-leg (mleg) orders — long straddle / long strangle → **SP-5.1b**
- Defined-risk spreads (vertical, iron condor) — requires `OptionSpec` engine extension + mleg `limit_price` sign resolution → **SP-5.2**
- Covered calls (need 100-share underlying position lookup) → out-of-scope, no SP-4 originator
- Naked short premium — barred at L3, structurally impossible on this account
- Roll/expiry automation — deferred (no live option strategy exists; positions allowed to expire until 5.1b)

## 2. Background & motivation

SP-4 (now LIVE, gate `OPENCLAW_SP4_INSTRUMENT_CLASS_AT_MINT=1`) makes the Saturday research stack ORIGINATE option candidates. `OptionSpec` is consumed only by `src/backtest/options_backtest.py`. **There is no live option exec path.** `src/execution/alpaca_executor.py` has a crypto intercept (`_route_crypto_order`, line 470) and an equity path; option orders fall through to the equity path's `_normalize_alpaca_symbol` (line 411) which returns `None` for OCC symbols → silent SKIP.

SP-5.0 grounded the Alpaca L3 envelope on the live paper account: L4 naked is barred, but everything below — long premium, defined-risk spreads, and **cash-secured short puts (L1 ⊂ L3 verified 2026-05-28)** — is accepted. SP-5.1a covers the single-leg portion of that envelope.

Five hard constraints surfaced by SP-5.0 drive the design:
1. **Options orders are RTH-only.** `position close` outside RTH → `422/42210000 "options market orders are only allowed during market hours"`. No extended-hours options. The lane MUST gate on `_alpaca_session_kind() == 'rth'`.
2. **mleg `limit_price` signing is unsolved.** Out of SP-5.1a scope (no mleg here), but documented to constrain SP-5.1b/5.2.
3. **Position-intent inference matters.** Broker reads `*_to_open` vs `*_to_close` from existing positions; specifying the wrong intent → 422. Lane must consult positions before submit OR derive intent from `Signal.direction` + current portfolio delta.
4. **Naked short premium is barred at L3** — but L1 short puts with cash collateral are accepted (verified). The lane must enforce a cash-collateral guard for short puts; without it, the same broker reject path will fire.
5. **`alpaca data option chain` returned empty during grounding** for some queries. Strike resolution must fail-closed (skip the submit) on a missing/empty quote, not silently submit at a default strike.

## 3. Architecture — single upstream intercept (mirrors crypto pattern)

Options are detected and handled **before** the equity session/qty logic. Everything non-option falls through unchanged, preserving the equity byte-identical invariant.

### 3.1 The routing helper

```
_route_option_order(order, equity, coid) -> dict | None
```

- Returns a **result dict** (same shape the equity path returns: `status`, `qty`, `notional`, `entry`, `order_id`, `tif`, `order_class`, `client_order_id`, …) when it handled an option order.
- Returns **`None`** to signal "not an option — fall through."
- Option detection: `order.get('instrument_class') == 'option'` (the sizer at `regime_blended_sizer_live.py:127-134` tags this when `OPENCLAW_INSTRUMENT_CLASS_ROUTING=1`) AND `order.get('option_spec')` is non-None (sizer passes through the spec). A missing spec returns `None` immediately → fall-through; no silent default-strike submit.
- **Internally branches on `order.get('close_only')`** the same way `_route_crypto_order` does (line 483 `if order.get('close_only'): return _route_crypto_close(...)`). Single call site in `execute_single`.

### 3.2 Single call site

Insert immediately AFTER the crypto intercept at `src/execution/alpaca_executor.py:1189`:

```python
_crypto_res = _route_crypto_order(order, equity, coid)
if _crypto_res is not None:
    return _crypto_res

# NEW — SP-5.1a
_option_res = _route_option_order(order, equity, coid)
if _option_res is not None:
    return _option_res
```

A non-option order returns `None` and the existing code runs verbatim. Order priority is crypto → option → equity; no order can be both crypto AND option (instrument_class is exclusive).

## 4. The option order path (inside the helper)

### 4.1 OCC symbol construction

`_build_occ_symbol(spec, strike, expiry) -> str`. Pure function (no I/O), unit-testable.
- `<root><YYMMDD><C|P><strike×1000, 8-digit zero-pad>`
- e.g. SPY, 2026-06-18, call, $750 → `SPY260618C00750000`

Inputs come from §4.2 (strike) and §4.3 (expiry). `spec.right ∈ {'call','put'}` maps to `C`/`P`.

### 4.2 Strike resolution — **fail-closed**

`_resolve_strike(spec, as_of) -> float | None`:
- `spec.strike_rule == 'atm'` → underlying spot from `alpaca data latest-trade --symbol <root>`, snap to nearest listed strike from `alpaca option contracts --underlying-symbols <root> --expiration-date <exp> --type call|put --limit N`. **Returns `None` if either call fails or the chain is empty.**
- `spec.strike_rule == 'fixed_moneyness'` → spot × `spec.moneyness`, snap to nearest listed.
- `spec.strike_rule == 'target_delta'` → query `alpaca data option chain --underlying-symbol <root>` for the closest-listed strike whose Greek δ matches `spec.target_delta` (within tolerance). **Returns `None` if chain is empty/stale.**
- On `None` → helper returns a `SKIP` result (mirrors crypto's price-fetch failure path), reason=`'option: strike unresolved'`. Audit row records the skip. No fall-through to default.

### 4.3 Expiry resolution

`_resolve_expiry(spec, as_of) -> date | None`: nearest monthly expiry ≥ `as_of + spec.dte_target` days, listed in `alpaca option contracts --underlying-symbols <root>`. Reuse `src/backtest/options_pricing.py:nearest_monthly_expiry` for the calendar arithmetic, then verify listing exists in the discovery call. Returns `None` if no matching contract → SKIP.

### 4.4 Side + position-intent inference

`_options_position_intent(spec, direction, current_positions) -> (side, intent)`:
- `direction='long'`, no existing position → `side='buy', intent='buy_to_open'`
- `direction='short'`, no existing position → `side='sell', intent='sell_to_open'`
- `direction='long'`, existing short → `side='buy', intent='buy_to_close'`
- `direction='short'`, existing long → `side='sell', intent='sell_to_close'`
- "existing position" lookup: `alpaca position list --jq '.[] | select(.symbol == "<OCC>")'`. Cached per execute_single call.

This resolves the test-5 422 (`inferred sell_to_close, specified sell_to_open`) class of error.

### 4.5 Cash-collateral guard for short puts — **executor-side**

`_cash_collateral_required(spec, strike, qty) -> float`: `strike × 100 × qty` for `right='put', side='sell'`; `0` otherwise (long premium uses option price × 100, which the sizer already accounts for).

Before submit:
1. Get `account_cash` from `alpaca account get --jq '.cash'`.
2. If `cash_required > account_cash`:
   - Reduce `qty` to `floor(account_cash / (strike × 100))`. If result is 0 → SKIP, reason=`'option: insufficient cash for short put'`.
   - Log the reduction (`log(f'short-put qty reduced {orig_qty}→{qty} for cash budget')`).
3. Else: submit at requested qty.

**Placement decision:** executor-side, NOT sizer-side. Mirrors the crypto pattern (executor enforces broker constraints). Sizer extension to pre-budget cash collateral is a future possible refinement (would let multiple short-put strategies share one collateral pool); deferred.

### 4.6 Session gate — RTH-only

Before any submit (open or close), check `_alpaca_session_kind() == 'rth'`. Outside RTH → SKIP, reason=`'option: market closed (RTH-only)'`. Mirrors the equity `close_only` market-closed path (line 1208-1213) but applies to opens too (because options can't extended-hours either).

This means: **after-hours regime redeploys (`OPENCLAW_REDEPLOY_EXTENDED_HOURS=1`) will SKIP all option orders** even when they fire equity/crypto orders. Documented invariant; not a bug.

### 4.7 Submit shape (open)

```
alpaca order submit \
  --symbol <OCC> \
  --qty <contracts> \
  --side <buy|sell> \
  --type limit \
  --limit-price <marketable_limit> \
  --time-in-force day \
  --position-intent <buy_to_open|sell_to_open> \
  --client-order-id <coid>
```

`--type limit` (not market) because the SP-5.0 grounding showed option market orders are RTH-only and fragile to wide bid-ask. `limit_price` for single-leg long = ask + 0.02; for single-leg short = bid - 0.02 (marketable but bounded). Quote source: `alpaca data option chain --underlying-symbol <root>` snapshot for the resolved OCC.

If the chain snapshot is empty/stale → SKIP, reason=`'option: no quote for limit price'` (same shape as the equity "no quote" skip at `:1271`).

### 4.8 Close path (close_only branch inside the helper)

`alpaca position close --symbol-or-asset-id <OCC>` (RTH-gate per §4.6). Single-leg positions have no leg-balance concern. Same shape as equity close path; market order is acceptable because we're inside RTH gate.

Partial-reduce: `--percentage <pct>` per the crypto close path (sizer emits `notional_usd = |delta|` and the helper computes pct).

### 4.9 Audit-record shape + migration 120

The returned dict populates the existing `record_submission` (alpaca_executor.py:340-378) fields:
- `order_id` → `alpaca_order_id`
- `qty` → `qty` (NUMERIC since mig 119; contracts as integer fits cleanly)
- `notional` → `notional_usd` = `contracts × 100 × limit_price`
- `entry` → `entry_price` = limit_price used
- `tif` → `'day'`
- `order_class` → `'simple'` (single-leg)
- `client_order_id` → `client_order_id`
- `ticker` → the OCC symbol (e.g. `SPY260618C00750000`) — fits in TEXT column unchanged

**Schema gap discovered 2026-05-29:** `alpaca_submissions` has no `instrument_class` column today (verified live DB). For audit slicing ("which submits were options?") and the doctor checks in §7 we need it.

**New migration 120** (additive, master-data-invariant-safe — column ADD only):
```sql
-- 120_alpaca_submissions_instrument_class.sql
-- SP-5.1a: tag submission rows by instrument_class for audit slicing.
-- Additive only; no DROP/DELETE. NULL = pre-migration / legacy 'equity'.
ALTER TABLE alpaca_submissions
  ADD COLUMN IF NOT EXISTS instrument_class TEXT NULL;
```

`record_submission` extended to read `order.get('instrument_class')` and write it to the new column. Readers (reconciler, doctor) default NULL → 'equity'. Apply via psycopg2 + idempotency check (psql not installed; mirrors SP-3.1 Phase D mig 119 application).

The reconciler treats option submits the same as equity (compares filled qty to submitted qty; partial-fills handled identically).

## 5. Sizer handler + sub-contract handling

`src/execution/instrument_class_sizer.py:22-55` already handles option orders: when `underlying_price` is on the order, it computes greeks-aware delta-dollar sizing and writes `scaled["contracts"] + scaled["delta_dollar"]`. When `underlying_price` is missing, it falls back to `notional × |delta|` with NO `contracts` field. **No sizer changes in SP-5.1a.**

**Sub-contract edge case** (executor-side handling):
- `order.get('contracts')` present and ≥ 1 → `qty = int(contracts)`, submit.
- `order.get('contracts')` present and 0 < contracts < 1 → `qty = 1` IF `notional_usd ≥ MIN_OPTION_NOTIONAL_USD` (default $100, configurable via env `OPENCLAW_OPTION_MIN_NOTIONAL_USD`), else SKIP, reason=`'option: sub-contract sizing below minimum'`.
- `order.get('contracts')` missing (fail-open fallback path) → compute `contracts = notional_usd / (limit_price × 100)`, then apply the same ≥1 / sub-contract / SKIP logic.
- `order.get('contracts')` ≤ 0 → SKIP, reason=`'option: zero contracts sized'`.

Rationale: an ATM call on a $750 underlying with delta=0.5 and $10k notional sizes to ~0.27 contracts; flooring to 1 means $37.5k delta-dollar exposure — a 3.75× over-size. Refuse-or-floor with an explicit minimum-notional gate is safer than silent flooring.

When `OPENCLAW_INSTRUMENT_CLASS_ROUTING=0`, no order is ever tagged `option`, so the helper is never reached → equity path byte-identical.

## 6. Gate

**New env var:** `OPENCLAW_OPTION_EXEC` (default OFF / unset).

Helper short-circuits to `None` at the top if `os.environ.get('OPENCLAW_OPTION_EXEC') != '1'`. Two-key activation:
- `OPENCLAW_INSTRUMENT_CLASS_ROUTING=1` → sizer routes options through the option sizing path (already in place).
- `OPENCLAW_OPTION_EXEC=1` → executor actually submits option orders.

With only `INSTRUMENT_CLASS_ROUTING=1`: options get sized but the executor returns `None` from the helper → falls through to equity path → `_normalize_alpaca_symbol` returns `None` for OCC → SKIP. (Sized but never submitted.) This is the soak state.

With both ON: full live option submit.

## 7. Audit / observability

- Every helper invocation writes one row to `alpaca_submissions` (success OR skip — skip rows have `order_id=NULL`, `instrument_class='option'`, and a `notes` field with the skip reason).
- Doctor check `option_exec_health` (new, slow=False, gated on `OPENCLAW_OPTION_EXEC=1`): in last 24h, ratio of skipped option rows to total option rows > 0.5 → WARN.
- System check `option_routing` (new, pipeline tag): with sizer routing ON, verifies a synthetic option order flows through the helper and produces a well-shaped dict.

## 8. Safety + invariants

- **Equity byte-identical when `OPENCLAW_OPTION_EXEC=0`** — helper returns `None` immediately; line 1189 dispatch falls through.
- **Crypto byte-identical** — `_route_crypto_order` runs first; only non-crypto reaches the option intercept.
- **No naked-short submit possible** — short puts go through the cash-collateral guard (§4.5); short calls would require a covered-call holdings check that is NOT in 5.1a scope and so will be REFUSED at the helper level (return SKIP, reason=`'option: short call requires covered-call lookup (not in 5.1a)'`).
- **Strike resolution is fail-closed** — empty/stale chain → SKIP, never default.
- **Quote-less submits forbidden** — no quote for limit price → SKIP, never market-order fallback.
- **RTH gate is total** — applies to opens AND closes AND partial reduces.
- **OCC symbol builder is pure** — unit-tested; no I/O; deterministic.

## 9. Known unsolved / deferred (documented)

- Roll automation — no live option strategy exists, positions allowed to expire until either (a) the first SP-4-originated candidate passes the promotion gate, or (b) 5.1b adds a daily roll scan. Document in spec, not a blocker.
- Covered-call holdings lookup — out of scope; helper REFUSES short calls.
- Vertical/condor — SP-5.2 (engine extension required).

## 12. Risks & mitigations

| Risk | Mitigation |
|---|---|
| Strike resolved silently to wrong value when chain endpoint flakes | Fail-closed in §4.2; SKIP with explicit reason |
| Cash-collateral guard misses a corner case (e.g. multiple concurrent short-put strategies) | Single-strategy execution model + sizer pre-allocates per-strategy budget; multi-strategy collateral pooling is documented as deferred |
| Position-intent mismatch 422 (test-5 class of error) | §4.4 lookup before submit; unit-tested |
| Equity path regression | `None`-fall-through + gate-parity test + helper short-circuits when gate OFF |
| After-hours redeploy fires option orders | RTH gate (§4.6) refuses; documented invariant |
| Naked short call somehow reaches helper | §8 explicit REFUSE on `right='call', side='sell'` |
| `option_spec` missing from a tagged-option order | §3.1 returns `None` → fall-through SKIP, never silent default |
