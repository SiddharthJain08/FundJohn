**Date:** 2026-06-03
**Status:** Approved (operator) — ready for implementation plan
**Branch:** `feat/sp5.1c-options-exec-activation` (off `feat/sp5.1b-ii-delta-hedge`)
**Predecessors:** SP-5.1a (single-leg exec, PR #16 merged main), SP-5.1b-i (mleg straddle/strangle, PR #17 merged main), SP-5.1b-ii (delta-hedge target-producer, branch `feat/sp5.1b-ii-delta-hedge`; FK fix `8e7719b`), SP-6 Phase A (EOD→open execution, merged main `c49011e`).

## Problem

The options-execution lane is built but **inert and disconnected**:

- **5.1b-i** (`_route_option_order` mleg lane) routes long straddles/strangles, but only when handed an `order` dict carrying `option_spec` + `instrument_class='option'`. Nothing builds that dict from a live signal.
- **5.1b-ii** (`compute_option_hedge_targets`) reads the `option_hedge_ledger`, computes net delta, and injects an FK-satisfied (`8e7719b`) APPROVED `is_hedge` equity row. But **nothing populates the ledger** — its only writer is the self-rewrite inside `compute_option_hedge_targets`, which merely re-stamps rows it already read. `load_active_hedges` is empty forever in production.
- **`engine.write_signals` drops `sig.option_spec`** — it serializes `signal_params` + `features` into the `signal_params` jsonb but never the `OptionSpec`. So an option strategy's spec dies at the engine→`execution_signals` boundary; the sizer/executor can never reconstruct the option order.
- The executor **refuses `hedge != 'none'`** (`alpaca_executor.py:818`, deferring to "the SP-5.1b-ii delta-hedge subsystem"), so even a correctly-specced delta-hedged structure won't route.
- There is **no option strategy** emitting a long delta-hedged structure to drive any of this. (`S_short_straddle_vrp` is SELL_VOL/short — out of the long-only envelope.)

**Root insight (from the 5.1b-ii real-DB round-trip):** the FK fix made the target-producer *connectable given a populated ledger*, but the ledger source, the option-signal propagation, and a driving strategy are all missing. This phase builds that connective tissue and proves the full chain — **inert** (gate-OFF/candidate-only). Live paper activation is a separate operator runbook.

## Goal & success criteria

`Done` = the full chain is **wired and proven inert**:

- An option strategy's `option_spec` survives `write_signals` → handoff → sizer → executor.
- A `hedge='delta'` LONG structure routes through the executor and **writes its `option_hedge_ledger` row on fill**.
- The next EOD `compute_option_hedge_targets` produces a hedge row from that ledger row (already verified end-to-end by `8e7719b`'s round-trip).
- **Equity behavior byte-identical with all gates OFF** (the load-bearing invariant).
- Proven by: unit tests per component + a real-DB round-trip (rolled back) covering signal→ledger→hedge-row + a gates-OFF dry-run.
- **No live fills in this phase.**

## Non-goals (deferred)

- SELL_VOL / short-vol structures — envelope stays long-debit-only.
- Live paper activation (flip gates, real fills, EOD→T+1) — separate operator runbook.
- Alpha quality of the reference candidate — it is a chain-driver proof, not an alpha claim.
- Roll/expiry management of the hedged structure beyond what 5.1b-i already does.
- BUY_VOL handling for non-option (equity) signals — normalization is scoped to the option order-build path only.

## Components

Each component is isolated, individually gated/inert, and independently testable.

### C1 — option_spec propagation (engine → handoff → sizer → executor)
Four sites carry the spec; the executor end (`order['option_spec']`) already exists.
- **`engine.write_signals`** (`src/execution/engine.py` ~line 926): when `sig.option_spec` is present, serialize it (dataclass → dict) into `params_clean['option_spec']`. Additive: `None` → key absent → equity rows byte-identical. **Ungated** (storing extra jsonb is harmless; gating lives at the executor).
- **`OptionSpec.from_dict(d)`** reconstruct helper in `src/strategies/base.py` (round-trips `asdict`). Fail-closed on malformed input (returns `None` → option routing skipped).
- **`trade_handoff_builder.py`**: carry `signal_params['option_spec']` + `instrument_class` onto the handoff order dict. (Task-0 grounding pins the exact emit site.)
- **`regime_blended_sizer._build_sized_payload` / `regime_blended_sizer_live`**: carry `option_spec` through to the order dict that reaches the executor; ensure `contracts` is set for option orders. (Task-0 grounding pins the exact site; today `apply_instrument_class_sizing` sizes option orders but the spec carry-through is unverified.)

### C2 — direction normalization
- `normalize_option_direction(d) -> 'long' | 'short' | None` in a shared util (mirror the `server.js:6696` mapping: LONG/BUY/BUY_VOL→long; SHORT/SELL/SELL_VOL→short; unknown→None fail-closed).
- Applied in the option order-build path (C1's sizer/handoff site) so the executor envelope (which expects `direction='long'`) receives a normalized value.
- **SELL_VOL → short** is normalized but then **refused by the long-only envelope** (C3) — documented, not an error.

### C3 — executor envelope-lift + ledger-write on fill
- **Lift the guard** at `alpaca_executor.py:818`: allow `hedge='delta'` **when `direction=='long'`** (reuse 5.1b-i's `_resolve_structure_legs` / `_build_mleg_legs_json` / submit). Keep refusing: non-long, and short-vol structures.
- **Ledger-write on fill:** after a successful `hedge='delta'` structure submit, write the `option_hedge_ledger` row (via `option_hedge.upsert_hedge_target` or a thin `create_hedge_ledger_row`): `option_strategy_id = <option sid>`, `underlying`, `structure_legs` = resolved legs (occ/right/strike/expiry), `contracts`, `target_hedge_qty = 0` (the EOD step computes the real target). Idempotent `ON CONFLICT (option_strategy_id, underlying)`.
- **Gating:** the whole branch is behind existing `OPENCLAW_OPTION_EXEC` + `OPENCLAW_OPTION_DELTA_HEDGE`. Gates OFF → byte-identical (refuses exactly as today). The single-leg + long-no-hedge mleg paths (5.1a/5.1b-i) stay byte-identical regardless.
- **Error handling:** if the structure submits but the ledger-write fails, log loudly (the EOD hedge would be absent → an unhedged long-gamma structure = bounded long-only risk, not catastrophic). Do not orphan; never abort a post-submit path.

### C4 — reference candidate
- `src/strategies/implementations/S_long_straddle_delta_hedged.py` (+ `.requirements.json`).
- Long ATM SPY straddle: `direction='BUY_VOL'`, `option_spec=OptionSpec(underlying='SPY', structure='straddle', hedge='delta', strike_rule='atm', dte_target=30, roll_dte=7)`, `instrument_class='option'`.
- Simple deterministic entry: hold one ATM straddle, re-open monthly (roll 7 DTE before expiry). A chain-driver, not alpha — entry rule is not load-bearing and may be simplified further at plan time.
- **Candidate-only** — never promoted. Backtest via the SP-4 options engine to populate metrics (expected to fail the 0.80 option Sharpe threshold — fine; mirrors `S_short_straddle_vrp`).

### C5 — verification (the deliverable)
- **Unit tests** per component: option_spec serialize/`from_dict` round-trip; direction normalizer (incl. SELL_VOL→short→envelope-refused); envelope-lift allows long-delta + still refuses non-long/short-vol; ledger-write-on-fill writes the expected row; handoff/sizer carry option_spec.
- **Real-DB round-trip (rolled back)** — extend `/tmp/hedge_roundtrip.py`'s pattern: write an option signal → `write_signals` → assert `execution_signals.signal_params->'option_spec'` present → (stub the executor structure-fill) → assert `option_hedge_ledger` row written → `compute_option_hedge_targets` emits the hedge row. Exercises the real schema seam end-to-end. Never commits (canonical tables).
- **Gates-OFF dry-run / regression:** equity byte-identical (the invariant) + option signals produce zero orders with gates off.
- **No live fills.**

## Data flow (gates-on narrative; lives behind the activation runbook)

```
option strategy (direction=BUY_VOL, option_spec: structure=straddle, hedge=delta)
  → engine.write_signals  [C1: option_spec → signal_params jsonb]
  → execution_signals row (instrument_class=option via resolver)
  → SP-6 EOD compute: COMPUTED → APPROVED (carried)
  → trade_handoff_builder [C1: option_spec + instrument_class onto order]
  → sizer._build_sized_payload [C1 carry + C2 normalize→long + size contracts]
  → executor _route_option_order [C3: route long mleg straddle + WRITE option_hedge_ledger on fill]
  → next EOD: compute_option_hedge_targets reads ledger → net delta
       → injects FK-satisfied APPROVED is_hedge equity row (8e7719b)
  → sizer net-aggregates hedge into target_usd (5.1b-ii T6a)
  → executor places the equity hedge order
  → loop closes (rehedge each EOD off the ledger)
```

## Gating summary

| Gate | Controls | Default |
|------|----------|---------|
| `OPENCLAW_OPTION_EXEC` | route option structures | OFF |
| `OPENCLAW_OPTION_DELTA_HEDGE` | hedge envelope + ledger-write + EOD hedge step | OFF |
| `OPENCLAW_INSTRUMENT_CLASS_ROUTING` | option sizing | OFF |
| (option_spec serialization) | additive, ungated — `None`→absent→byte-identical | n/a |

All gates OFF ⇒ equity byte-identical (regression-tested).

## Risks & mitigations

- **Live-critical surfaces:** `engine.write_signals` + the sizer affect *all* strategies. Mitigation: option_spec serialization is additive (`None`→absent); normalization + carry are scoped to `instrument_class=='option'` orders; equity-byte-identical regression is the gate.
- **Ledger-write orphan:** structure fills but ledger-write fails → unhedged long-gamma. Mitigation: long-only debit (bounded risk), loud logging, guarded write, never abort post-submit.
- **Unverifiable-plumbing trap (the recurring blind spot):** mocked-both-sides tests miss seam bugs. Mitigation: the real-DB round-trip (C5) is mandatory, not optional — it is what caught the FK bug.
