# SP-5.1b Grounding Spike — Snapshot (2026-06-01, paper account, RTH)

Operator-approved live grounding spike (Task 0) for the mleg long straddle/strangle exec lane. All submits were **non-marketable (rest) + cancelled — no fills**. Baseline positions 13 → 13 after every probe; no residual option positions or open orders left.

## Findings

### 1. mleg submit REQUIRES a top-level `--qty` (CRITICAL — caught a build bug)
`order submit --order-class mleg --legs '[...]'` **without** `--qty` → `422 {"code":42210000,"error":"qty must be > 0"}`. **With** `--qty 1 --legs '[{...ratio_qty:"1"...}×2]'` → **ACCEPTED** (`status=pending_new`, `order_class=mleg`, `leg_count=2`).
- **Semantics:** total contracts per leg = top-level `--qty N` × per-leg `ratio_qty R`. For a 1:1 long straddle/strangle of N structures the correct form is **`--qty N`, each leg `ratio_qty "1"`**.
- **Build impact:** the original mleg submit omitted `--qty` and set `ratio_qty=str(contracts)` (would 422, and double-count if naively patched). **Fixed in commit `961738d`** (`--qty str(raw_qty)` + `ratio_qty="1"`).

### 2. mleg DEBIT `limit_price` convention = net debit "pay ≤ X" (CONFIRMED)
A long straddle submitted at `--limit-price 0.50` (a ~$30 straddle) was **accepted and rested** (did not fill at 0.50). So the mleg package `limit_price` for a long debit is the **net debit you'll pay** — the build's `net_limit = Σ(ask) + slip` (positive debit) is the correct convention.

### 3. `position_intent` = `buy_to_open` on both legs — ACCEPTED, no 422
The resting straddle showed both legs `side=buy, position_intent=buy_to_open, qty=1`. No inferred-intent conflict (the SP-5.0 test-5 422 class did not recur for a fresh open). The build's per-leg `_options_position_intent` is correct.

### 4. Atomicity — one mleg order carries both legs
The accepted order is a single `order_class=mleg` with `leg_count=2` (one order id, both legs). All-or-nothing package semantics (no per-leg partials observed in the resting/cancel cycle).

### 5. Chain greeks populated live (CONFIRMED — `_option_chain_greeks` field-path)
`data option chain --underlying-symbol SPY --expiration-date <E> --type {call,put} --strike-price-gte/lte` returns `snapshots[<OCC>].greeks.delta` non-null (e.g. call δ=0.7914, put δ=−0.2394 at the 738 strike). The build's `_option_chain_greeks` parse path (`snapshots[occ].greeks.delta`) is validated, and call/put delta signs match the strangle abs-delta matching logic. (Post-close greek availability for 5.1b-ii's EOD hedge pass was NOT separately probed — verify when building 5.1b-ii.)

### 6. CREDIT (sell-to-close) limit-sign — NOT probed (and moot for this build)
A sell-to-open straddle would be a naked short (barred at L3 per SP-5.0), so the credit-sign for a *close* cannot be probed without first holding a long structure. **Moot:** the build's close path (`_route_mleg_close`) closes the actually-held legs via per-leg `position close` — credit-sign-independent. If a future mleg sell-to-close *package* is desired, probe the credit-sign then.
