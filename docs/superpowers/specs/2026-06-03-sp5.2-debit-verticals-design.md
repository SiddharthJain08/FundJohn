# SP-5.2 — Debit Vertical Spreads (exec primitive) (design)

**Date:** 2026-06-03
**Status:** Approved (operator) — ready for implementation plan
**Branch:** `feat/sp5.2-debit-verticals` (off `main` `c49011e`)
**Predecessors:** SP-5.1a (single-leg exec, in main), SP-5.1b-i (mleg straddle/strangle, in main), SP-5.0 grounding (`docs/superpowers/specs/2026-05-27-sp5-alpaca-options-snapshot.md`).

---

## Problem

The options-exec lane routes single-leg longs (5.1a) and long straddles/strangles (5.1b-i), both live-proven via supervised paper smokes. The next defined-risk structure in the L3 envelope is the **vertical spread**. SP-5.0 confirmed live (real submits) that the account (`options_approved_level: 3`) accepts defined-risk multi-leg spreads — a **short call vertical filled live** — while naked short premium is barred (403 uncovered). SP-5.2 adds the **debit (long) vertical** as an execution primitive.

Scope is deliberately limited to **debit** verticals because:
- A debit vertical is *bought* at a net debit, reusing the **proven `pay net ≤ X` mleg limit semantic** (same as the long straddle) — no new signing risk.
- **Credit** verticals + iron condors hit the **unsolved mleg credit-spread `limit_price` signing question** (SP-5.0 §4a: a "$50 credit" positive limit on a sell-spread filled at ~$5 fair value → limit appears unsigned `pay-net ≤ X`, NOT "receive ≥ X credit"). That must be resolved by an Alpaca-docs + debit-shape probe before any production credit submit, and is deferred to **SP-5.2b**.

## Goal & success criteria

`Done` = the lane can route a long debit vertical, proven inert + once live:
- A debit vertical (bull call spread or bear put spread) routes as a single mleg buy package at a net-debit limit, with the two legs at different strikes / opposite sides (buy near, sell far).
- Close uses the proven per-leg `position close` path (no net-credit package → the signing question never arises).
- **Equity + existing option paths (single-leg, straddle, strangle) byte-identical** with gates off and on.
- Unit-tested; then **one supervised live paper smoke** (real debit-vertical fill → per-leg close → both legs flat-verified).

## Non-goals (deferred)

- **Credit verticals + iron condors** → SP-5.2b (gated on the mleg credit-sign grounding).
- **A driving vertical strategy + SP-4 backtest-vertical pricing** → until a vertical strategy is created/promoted. 5.2 is an exec primitive (mirrors how 5.1a/5.1b-i shipped without a driving strategy).
- **Net-credit close package** (sell-to-close the spread as one mleg) → would hit the credit-sign question; per-leg close is used instead.
- The 5.1b-ii/5.1c hedge + signal-propagation stack — 5.2 is independent, off `main`.

## The structure

A debit vertical = two legs, **same right, different strikes, opposite sides**, net debit:
- **Bull call spread** (`right='call'`): buy near (lower-strike, ATM-ish) call + sell far (higher-strike) call. Profits if underlying rises. Net debit.
- **Bear put spread** (`right='put'`): buy near (higher-strike, ATM-ish) put + sell far (lower-strike) put. Profits if underlying falls. Net debit.

It is always *bought* (long the package) → the existing long-only envelope guard fits; bull/bear lives in `right`. The short far leg is **defined-risk-covered** by the long near leg (L3 accepts this — the SP-5.0 short-call-vertical filled).

## Components

### C1 — `OptionSpec` extension (`src/strategies/base.py`)
- Add `'vertical'` to the `structure` domain (`single | straddle | strangle | vertical`).
- Add one optional field `spread_width_pct: float = 0.03` — the far (short) leg's strike offset as a fraction of spot. Near leg uses the existing `strike_rule`/`target_delta`/`moneyness`; far strike = near strike `± spread_width_pct × spot`, rounded to a listed strike (`+` for a call spread, `−` for a put spread).
- Additive/optional with a default → equity and existing option specs serialize/behave byte-identically (`asdict`/`from_dict` unaffected; the field is just present with its default).

### C2 — Side-aware structure helpers (`src/execution/alpaca_executor.py`)
The three structure helpers become per-leg-side aware; straddle/strangle (uniform-buy) keep identical output.
- **`_resolve_structure_legs`** gains a `vertical` branch returning the two legs **with intended side**: near `(right, near_strike, 'buy')` + far `(right, far_strike, 'sell')`. Near strike via `_resolve_strike` (reusing the spec's strike_rule); far strike = near ± `spread_width_pct×spot` snapped to a listed strike (reuse the listed-strike lookup). Fail-closed → None if either strike unresolved. Straddle/strangle branches return their legs tagged `'buy'` (backward-compatible).
- **`_structure_net_quote`** becomes side-aware: net = Σ(buy-leg ask) − Σ(sell-leg bid). For a debit vertical that's `near_ask − far_bid` (a positive debit). For straddle/strangle (all-buy) it's the same sum as today → byte-identical.
- **`_build_mleg_legs_json`** takes **per-leg side** and emits `buy_to_open` for buy legs / `sell_to_open` for sell legs (via `_options_position_intent` per leg). Straddle/strangle pass all-`buy` → identical JSON to today.

### C3 — Route + close (`alpaca_executor.py:_route_option_order`)
- Add `'vertical'` to the allowed-structure set (the `structure not in ('single','straddle','strangle')` skip-guard, `alpaca_executor.py` ~line 781) and route it through the straddle/strangle mleg branch (`structure in ('straddle','strangle','vertical')`). Submit: mleg buy package, `--limit-price` = net debit (`round(net_debit + 0.02, 2)` marketable pad; `pay ≤ X`). Long-only guard unchanged (a debit vertical's order direction is `long` = buy the package). Hedge guard unchanged (vertical has `hedge='none'`).
- **Close = per-leg `position close`** (reuse 5.1b-i's `_route_mleg_close` / `_held_option_legs`): reads held legs from the book (long near +N, short far −N), closes each, per-leg `_options_current_qty` flat-verify. No net-credit mleg package.

### C4 — Envelope + gating
- Allowed structures: `single | straddle | strangle | vertical`. Still refuse: non-long order direction; `hedge != none` on a vertical (n/a — verticals are unhedged defined-risk); credit/condor (not in 5.2). Behind existing `OPENCLAW_OPTION_EXEC`.
- Gates-off → `_route_option_order` returns None → equity byte-identical. Single-leg / straddle / strangle paths byte-identical (the side-aware helpers are backward-compatible for uniform-buy).

### C5 — Verification
- **Unit tests:** vertical leg resolution (buy near / sell far, correct strikes for call-spread vs put-spread, far strike snapped via `spread_width_pct`); side-aware `_structure_net_quote` (debit = near_ask − far_bid); `_build_mleg_legs_json` per-leg sides (`buy_to_open`/`sell_to_open`); **straddle/strangle still emit uniform-buy + same net-sum (byte-identical regression)**; envelope allows long vertical, still refuses non-long + credit; gates-off returns None.
- **Supervised live smoke** (`scripts/sp5_2_smoke.py`, operator-OK at fire time, RTH): buy 1 SPY debit **call** spread (near ≈ ATM, far ≈ +3% via `spread_width_pct=0.03`, small net debit), poll to terminal, per-leg close, **confirm BOTH legs flat** (re-flatten once on residual, fail-on-orphan). Mirrors `scripts/sp5_1b_smoke.py`. Plus a gate-OFF sub-smoke (structure order → None).

## Data flow (gates-on)

```
order {instrument_class:'option', direction:'long', option_spec: structure=vertical, right=call, spread_width_pct=0.03}
  → _route_option_order (OPENCLAW_OPTION_EXEC=1, long-only ✓, structure=vertical ✓)
  → _resolve_expiry → _resolve_structure_legs(vertical) → [(call, nearK, buy), (call, farK, sell)]
  → _structure_net_quote (side-aware) → net_debit = near_ask − far_bid
  → _build_mleg_legs_json (buy_to_open near, sell_to_open far)
  → alpaca order submit --order-class mleg --qty N --legs ... --limit-price <net_debit+0.02> --tif day
  → (smoke) poll terminal → per-leg position close → flat-verify
```

## Gating summary

| Gate | Controls | Default |
|------|----------|---------|
| `OPENCLAW_OPTION_EXEC` | route option structures incl. vertical | OFF |

Gate OFF ⇒ equity byte-identical; existing single/straddle/strangle byte-identical regardless (side-aware helpers backward-compatible).

## Build approach

- Branch `feat/sp5.2-debit-verticals` off `main` (`c49011e`). Independent of 5.1b-ii/5.1c.
- Subagent-driven TDD, fresh implementer per task + 2-stage review on the executor change; sequential subagents (2-core VPS; `nice -n 19`).

## Risks & mitigations

- **Byte-identical regression on straddle/strangle:** the side-aware refactor of the three shared helpers is the main risk. Mitigation: straddle/strangle pass uniform-`buy` and MUST produce identical legs-JSON + identical net-sum; a regression test asserts this (run `tests/test_options_execution_lane.py` + the 5.1b smoke-shape tests).
- **Far-strike not listed:** `spread_width_pct×spot` may not land on a listed strike → snap to the nearest listed strike; fail-closed (skip) if none in range.
- **Credit on close:** avoided by construction — per-leg close, never a net-credit package. The credit-sign question stays out of 5.2.
- **Short leg mis-read as naked:** the mleg package pairs the legs so the broker sees defined risk (SP-5.0 short-call-vertical filled). The smoke confirms acceptance live before any reliance.
